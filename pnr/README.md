# Local replay of the Tiny Tapeout CMOS5L hardening flow

The signoff flow is the Tiny Tapeout `gds` GitHub workflow
(`TinyTapeout/tt-gds-action@ihp-cmos5l`, LibreLane 3.1.0.dev3,
`ihp-sg13cmos5l`). This directory runs the same LibreLane flow on a
workstation without Docker or Nix, so that configuration and RTL changes can
be checked for timing before pushing.

```
pnr/setup.sh                                   # once: venv with LibreLane, pyosys 0.66, openroad
PDK_ROOT=/path/IHP-Open-PDK TT_TOOLS=/path/tt-support-tools pnr/run_local.sh mytag
python3 pnr/ll_report.py pnr/out/mytag/runs/mytag --steps --check 3.0
```

* `PDK_ROOT`: IHP-Open-PDK checkout (CI uses revision
  `2bbec755dc67ca3db0261c3d6163e15735d66710`) with `ihp-sg13cmos5l` and
  `ihp-sg13g2/libs.tech/librelane/openrcx` (the CMOS5L OpenRCX rules file is
  a symlink to it).
* `TT_TOOLS`: `tt-support-tools`, branch `ihp-sg13cmos5l` (6x4 DEF template).
* `run_local.sh` builds `config_merged.json` the way `tt_tool.py` does
  (project `src/config.json` overridden by the Tiny Tapeout keys) and runs
  the Classic flow up to the three-corner post-route STA.
* `ll_report.py` also reads the `runs/wokwi` folder of a `GDS_logs` CI
  artifact; the `timing_signoff` job of `.github/workflows/gds.yaml` runs it
  with `--check 3.0`.

## What is and is not the same as CI

| | Local replay | CI |
|---|---|---|
| LibreLane scripts, flow order, `config.json` | 3.1.0.dev3 | 3.1.0.dev3 |
| Synthesis | Yosys 0.66 (`pyosys`) | Yosys 0.66 |
| OpenROAD | pip `openroad` bindings behind `shim/or_shim.py` | LibreLane's pinned build |
| Extraction + STA | same rules and scripts | |
| Magic / KLayout DRC, LVS, TT precheck | not run | run |

Checked on commit 011b2fb (the first CMOS5L CI run):

* the synthesized netlist is identical to the CI netlist (same 50 884
  lines; only the "Generated by" comment differs),
* OpenRCX + STA on the CI's routed DEF give the CI's slacks to six digits
  in all three corners (-5.234297 / 4.263402 / 9.799762 ns setup),
* placement, CTS and routing differ in detail (different OpenROAD build):
  instance counts within 0.2 %, estimated wirelength within 3 %.

Checked again on commit 359f960 (v3, final configuration), full flow on both
sides:

| | Local replay (F1) | CI |
|---|---|---|
| Setup slack typ / slow / fast | +10.27 / +4.68 / +13.53 ns | +10.57 / +5.13 / +13.74 ns |
| Hold slack typ / slow / fast | +0.34 / +0.69 / +0.14 ns | +0.33 / +0.68 / +0.13 ns |
| Cells, area | 11 925, 211 053 µm² | 11 932, 211 497 µm² |
| Global-route / routed wirelength | 887 / 669 mm | 914 / 678 mm |
| Worst slow-corner path | prefetch (branch decision → read mux tree → `instr`) | same |

The replay was 0.45 ns pessimistic in the slow corner and 0.01 ns optimistic
on hold.

The pip OpenROAD build needs three workarounds, all in `shim/compat.tcl`:
`initialize_floorplan` / `make_tracks` / `insert_tiecells` are re-implemented
(the `ifp::` Tcl commands crash in the Python bindings; the resulting
rows and tracks are identical to the CI floorplan DEF), `global_connect`
takes no flags, and `repair_antennas` lacks `-allow_congestion`.

## Why `src/config.json` deviates from the template

The first CMOS5L CI run (commit 011b2fb, template configuration) passed
every Tiny Tapeout check but had **-5.23 ns** setup slack in the slow corner
(LibreLane only fails on typical-corner violations for this PDK). Two causes,
both visible in the run's own logs:

1. **Wire RC is under-estimated during optimization.** The CMOS5L PDK
   configuration ships an empty `LAYERS_RC`, so placement/CTS/global-route
   timing repair use LEF-derived values: 9.7e-5 pF/µm and 0.39 Ω/µm. OpenRCX
   on the routed design gives 1.7e-4 pF/µm and 1.2 Ω/µm (fit over 2 612
   nets). The resizer therefore saw "no setup violations" and left
   minimum-size gates on long nets. `LAYERS_RC` / `VIAS_R` in `config.json`
   carry the SG13G2 values for Metal1–Metal4 (same BEOL).
2. **Congestion.** CMOS5L routes signals on Metal2–Metal4 only, with a single
   horizontal layer (Metal3). At 60 % placement density detailed routing
   started from 8 883 violations, needed 34 iterations (2 h 43 min in CI)
   and detoured heavily: one two-pin net on the critical path was routed
   998 µm for a 247 µm distance. Density is lowered, and design/timing repair
   after global routing is switched on.

The resizer margins (4.5 ns) ask for more slack than the 3 ns target
because the remaining estimate-to-signoff error is up to about 1 ns in the
slow corner. Hold margins are 0.15 / 0.10 ns (template: 0.1 / 0.05) because
the fast-corner hold slack after routing lands close to the post-GRT margin.

## Results of the experiments (local replay)

| Run | RTL | Configuration | Slow setup | Fast hold | DRT |
|---|---|---|---|---|---|
| CI | v2 | template (60 %, LEF RC) | **−5.23** | +0.11 | 34 it., 2 h 43 |
| E1 | v2 | RC fix, 40 %, post-GRT repair, margin 3.5 | +3.75 | +0.10 | 5 it. |
| E3 | v3, read mux left to synthesis | as E1 | +2.70 | +0.08 | 5 it. |
| E4 | v3, mux4 tree | as E1 | +3.78 | +0.10 | 5 it. |
| E5 | v3 final RTL | as E1, margin 4.5 | +4.87 | +0.09 | 5 it. |
| E6 | v3 final RTL | as E5 without post-GRT repair | **+0.95** | +0.09 | 6 it. |
| E7 | v3 final RTL | E5 + Metal2/3 estimate layers, slew margins 50/45 | +5.02 | +0.05 | 5 it. |
| F1 | v3 final RTL | **final `src/config.json`** (E7 + hold margins 0.15/0.10) | **+4.68** | **+0.14** | 6 it., 13 min |
| E9 | v3 final RTL | final without the two post-GRT repair steps | +3.30 | +0.15 | 8 it. |
| E8 | v2 (011b2fb) | final `src/config.json` | +4.81 | +0.12 | 5 it., 16 min |
| **CI** | **v3 (359f960)** | **final `src/config.json`** | **+5.13** | **+0.13** | 28 min |

E8 is the like-for-like reference for F1: the same flow and configuration on
the v2 RTL (10 347 cells, 154 059 µm² = 17.1 %). The v3 extensions cost
0.13 ns of slow-corner slack and 6.3 points of utilization.

E3–E5 also used slew repair margins of 35 % / 30 % (E1: LibreLane defaults
20 % / 10 %). All runs: 0 routing DRC errors, 0 antenna violations after repair. F1 has no
slew or capacitance violations in any corner; its reports are in
`reports/v3-local/`.

LibreLane documents the two post-global-route repair steps as experimental
("may result in hangs and/or extended run times"). They took 21 s and 41 s
in run F1 and 24 s and 65 s in the CI run on 359f960. Should they misbehave
in a later run, set `RUN_POST_GRT_DESIGN_REPAIR` and
`RUN_POST_GRT_RESIZER_TIMING` to 0: run E9 shows the design still meets the
3 ns target without them, with 0.3 ns instead of 1.7 ns to spare.

Warnings of the CI run that are expected:

* `[RSZ-0062] Unable to repair all setup violations` (post-CTS resizer): the
  4.5 ns margin is not reachable on every endpoint at that stage; the signoff
  numbers are what count.
* `[EST-0026] Missing route to pin … in net …` (both post-GRT steps, more
  than 1000 messages each): parasitic estimation from global routes found no
  route for some pins. It affects only what the two repair steps see; signoff
  STA uses OpenRCX parasitics of the detailed routes, and LVS is clean.
* `klayout__drc_error__count not reported`: LibreLane does not run KLayout
  DRC for this PDK; the Tiny Tapeout precheck does (0 violations).
